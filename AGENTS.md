# AGENTS

- Validate skill changes with `scripts/validate-skills [skill-name ...]`. The repository command validates Agent Skills fields, the supported Claude Code extensions and each `SKILL.md`'s size through an isolated `uv` environment with pinned PyYAML.
- After rewording or cutting a skill that has a probe file in `evals/`, run `scripts/eval-skills <skill-name ...>`. It calls Opus and Sol through the `claude` and `codex` CLIs, and the edit holds when `after` passes every probe that `before` passes. The command exits non-zero when a probe regresses. Then don't sync, commit, or leave the edit in `/home/james/Projects/skills`, whose skills are live as soon as a file is saved. Revise the edit and rerun that probe until the `after` arm passes it, or report the failing probe with its output and wait for my decision. To show a regression was noise, rerun the unchanged text, and count it as noise only when the `after` arm passes, whatever the exit status. Rerun with `scripts/eval-skills <probe-file> --probe <probe-id> --out <new-directory>`, where `<probe-file>` is the name of the `evals/*.toml` file that holds the probe, adding `--kinds live` for a live probe. Use a new directory, because an unchanged rerun returns cached answers.
- Run `scripts/test-skills` for script changes.
- Run the sync script after all changes are completed and validated. When a change moves a skill from `external-skills.json` into this repository, run `scripts/setup-external-skills` first, because the sync script reports a conflict while the external copy is installed.
- After skill changes are committed and pushed, run `scripts/update-fleet-skills` only when asked to update the fleet. It changes other machines.
