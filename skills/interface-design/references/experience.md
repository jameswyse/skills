# Experience first

The product is the experience. When implementation convenience conflicts with user delight, choose delight.

- Say no to features, controls, and options that do not earn their place.
- Ship fewer polished features instead of more rough ones.
- When the user asked to explore a design, prototype before committing to production code. Design decisions are cheaper in a disposable prototype.
- Refine transitions, alignment, spacing, feedback, and error states.
- Improve the central workflow. Each feature should support it or be removed.

For an interface, the user is the person completing the task. Explain tradeoffs from their seat. Foundations should serve their experience. Foundational thinking governs the sequence of work. This reference governs the target.
